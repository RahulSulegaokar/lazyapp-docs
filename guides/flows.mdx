---
title: "Flows"
description: "Create, publish, and send WhatsApp Flows — and collect submissions."
---

WhatsApp **Flows** are Meta-hosted interactive forms (screens of inputs and navigation) opened from a chat. LazyApp stores a workspace mirror of each flow, publishes to Meta, and records completions on webhooks and [`GET /v1/flows/{flow}/responses`](/api-reference/flows/list-flow-responses).

Do not confuse Flows with [workflows](/api-reference/workflows/list-workflows) (LazyApp automation graphs) or [templates](/sending/templates) (approved outbound message shells). A Flow can be attached to a template button or sent as an interactive message inside the [24-hour window](/sending/messages#the-24-hour-window).

<Warning>
**Coexistence numbers** report `flows: false` and `flows.data_endpoint: false` on [`GET /v1/capabilities`](/concepts/capabilities). Build Flow onboarding for Cloud-API-only numbers. See [WhatsApp Business app coexistence](/guides/connecting-whatsapp#whatsapp-business-app-coexistence).
</Warning>

## Check before you build

```bash
curl https://lazyapp.in/v1/capabilities \
  -H "Authorization: Bearer $LAZYAPP_API_KEY"
```

| Capability | Meaning |
| --- | --- |
| `flows` | Create / publish / send Flows on this connection |
| `flows.data_endpoint` | Dynamic Flows with your HTTPS data endpoint |
| `messages.flow` | Interactive `type: flow` sends |

**Required scope for management APIs:** `flows:write` (list, create, publish, deprecate, responses, endpoint health). Sending a Flow message also needs `messages:send`.

## Lifecycle

```
draft → publish → published (or throttled) → deprecate → deprecated
```

Meta may also mark a flow `blocked` or `throttled`. Only **`published`** and **`throttled`** are sendable. Published flows cannot be edited in place — [duplicate](#duplicate) into a new draft, then publish.

## Create a flow

```bash
curl -X POST https://lazyapp.in/v1/flows \
  -H "Authorization: Bearer $LAZYAPP_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: flow-lead-1" \
  -d '{
    "name": "Lead capture",
    "categories": ["LEAD_GENERATION"],
    "flow_json": {
      "version": "7.0",
      "screens": [
        {
          "id": "LEAD",
          "terminal": true,
          "layout": {
            "type": "SingleColumnLayout",
            "children": []
          }
        }
      ]
    }
  }'
```

| Field | Required | Notes |
| --- | --- | --- |
| `name` | Yes | Max 200 characters |
| `categories` | Yes | At least one Meta Flow category string (for example `LEAD_GENERATION`, `APPOINTMENT_BOOKING`) |
| `flow_json` | Yes | Object or JSON string — must include `screens`, unique screen `id`s, and at least one `terminal: true` screen |
| `data_endpoint_uri` | No | **HTTPS** URL of your server for dynamic Flows. LazyApp forwards decrypted requests to it |
| `public_key` | No | Accepted for compatibility and ignored: LazyApp manages the number's key |

Invalid Flow JSON returns `422` with field errors before Meta is called. On success the flow is created at Meta and stored as `draft` with a `provider_flow_id`.

```json
{
  "uuid": "9f8b1c2d-4e5f-4a6b-8c7d-0e1f2a3b4c5d",
  "name": "Lead capture",
  "status": "draft",
  "categories": ["LEAD_GENERATION"],
  "provider_flow_id": "flow-777",
  "version": 1,
  "data_endpoint_uri": null,
  "endpoint_health": null,
  "published_at": null,
  "created_at": "2026-09-02T08:00:00+00:00"
}
```

Console starters (`lead_capture`, `appointment_booking`, and others) produce the same draft shape without writing Flow JSON by hand.

## Publish and deprecate

```bash
curl -X POST https://lazyapp.in/v1/flows/9f8b1c2d-4e5f-4a6b-8c7d-0e1f2a3b4c5d/publish \
  -H "Authorization: Bearer $LAZYAPP_API_KEY" \
  -H "Idempotency-Key: flow-lead-1-publish"
```

Publishing emits `flow.published` (or `flow.failed` on Meta error). Deprecate with `POST …/deprecate` when you want to stop attaching the flow to new messages. If Meta later throttles or blocks the flow because its endpoint is failing, you get `flow.status_changed`.

## Update or delete a draft

`PUT /v1/flows/{flow}` takes the same body as create and replaces the draft. A published flow answers `422` with `code: flow_not_editable`.

`DELETE /v1/flows/{flow}` deletes a draft at Meta and in LazyApp, and answers `204`. A published flow answers `422` with `code: flow_not_deletable`: deprecate it instead.

## Can it be sent?

Sending a flow depends on the flow, your WhatsApp Business account, your Meta business and LazyApp's app. Meta rates each one and LazyApp asks for your number specifically:

```bash
curl https://lazyapp.in/v1/flows/9f8b1c2d-4e5f-4a6b-8c7d-0e1f2a3b4c5d/health \
  -H "Authorization: Bearer $LAZYAPP_API_KEY"
```

```json
{
  "can_send_message": "BLOCKED",
  "problems": ["endpoint_uri: You need to set the endpoint URI before you can send or publish a flow."],
  "notes": [],
  "entities": [ { "entity_type": "FLOW", "can_send_message": "BLOCKED", "errors": [ … ] } ]
}
```

`can_send_message` is `AVAILABLE`, `LIMITED` (sendable, see `notes`) or `BLOCKED` (see `problems`). The result is kept on the flow as `can_send_message`. In the console, use **Check it can be sent** on a flow.

## Copy flows from another number

If your workspace has numbers on two WhatsApp Business accounts owned by the same Meta business, copy the flows from one into the workspace's main account:

```bash
curl -X POST https://lazyapp.in/v1/flows/copy \
  -H "Authorization: Bearer $LAZYAPP_API_KEY" -H "Content-Type: application/json" \
  -d '{ "source_connection_uuid": "…", "flow_names": ["appointment-booking"] }'
```

Leave out `flow_names` to copy every flow (Meta copies up to 100 per request). Copies keep their names and status; a name that already exists is reported under `failed` with Meta's reason. In the console: **Flows → ⋯ → Copy flows from another number**.

## Data endpoint

Meta calls a data endpoint for flows that load data while the customer fills them in. That traffic is encrypted with a key pair registered on your number. LazyApp is always the endpoint Meta calls: it keeps the key, decrypts each request and either answers from the Flow JSON (flows without a `data_endpoint_uri`) or forwards plain JSON to your `data_endpoint_uri`, signed with `X-LazyApp-Signature: sha256=…` using the flow's signing secret. Your reply is encrypted back for Meta. Set up the number's key once under **Flows → Secure flow connection**.

### Data endpoint health

Probe it the way Meta does:

```bash
curl https://lazyapp.in/v1/flows/9f8b1c2d-4e5f-4a6b-8c7d-0e1f2a3b4c5d/endpoint-health \
  -H "Authorization: Bearer $LAZYAPP_API_KEY"
```

```json
{
  "reachable": true,
  "status": 200,
  "latency_ms": 84,
  "error": null,
  "checked_at": "2026-09-02T08:05:00+00:00"
}
```

LazyApp sends an encrypted, signed `ping` to its own hosted endpoint, exactly as Meta does, and records the result on the flow.

## Send a Flow message

Inside the customer-service window (or via a template that opens the Flow):

```bash
curl -X POST https://lazyapp.in/v1/messages \
  -H "Authorization: Bearer $LAZYAPP_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: flow-send-1" \
  -d '{
    "type": "interactive",
    "to": "+919812345670",
    "interactive": {
      "type": "flow",
      "body": { "text": "Complete the form" },
      "action": {
        "name": "flow",
        "parameters": {
          "flow_message_version": "3",
          "flow_id": "flow-777",
          "flow_token": "session-token-1",
          "flow_cta": "Open",
          "flow_action": "navigate",
          "flow_action_payload": {
            "screen": "LEAD",
            "data": {}
          }
        }
      }
    }
  }'
```

Use Meta's `provider_flow_id` as `flow_id`. Workflows can launch published flows with a generated `flow_token` via the `launch_flow` node.

## Collect responses

When the contact finishes, Meta delivers an interactive `nfm_reply`. LazyApp:

1. Stores a `WhatsAppFlowResponse` linked to the flow  
2. Emits `flow.response_received`  
3. Exposes the payload on the list API  

```bash
curl "https://lazyapp.in/v1/flows/9f8b1c2d-4e5f-4a6b-8c7d-0e1f2a3b4c5d/responses?limit=25" \
  -H "Authorization: Bearer $LAZYAPP_API_KEY"
```

```json
{
  "data": [
    {
      "uuid": "…",
      "flow_token": "tok-123",
      "payload": {
        "flow_token": "tok-123",
        "full_name": "Ada Lovelace"
      },
      "received_at": "2026-09-02T08:10:00+00:00"
    }
  ],
  "next_cursor": null
}
```

Prefer webhooks for live capture; list + console CSV export are for backfill and ops.

## What we skip (Zernio-style)

| Zernio surface | LazyApp |
| --- | --- |
| `/v1/whatsapp/flows/*` | Flat `/v1/flows/*` |
| `POST …/flows/send` | [`POST /v1/messages`](/sending/messages) interactive |
| Flow JSON / versions / preview as separate public routes | Create + show (`flow_json` on retrieve); versioning via console clone |
| Managed data-endpoint hosting | LazyApp hosts and encrypts; your `data_endpoint_uri` gets plain signed JSON |
| `accountId` on every call | Workspace from API key |
