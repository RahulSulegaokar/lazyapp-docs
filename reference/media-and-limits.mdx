Quick reference for media uploads, WhatsApp limits, and failures. Upload mechanics and retention are in [Media](/sending/media); HTTP rate caps are in [Rate limits](/reference/rate-limits).

## Upload limits

WhatsApp sets a size limit for each kind of file, and LazyApp applies exactly those limits to every upload. Checking at upload time means a file WhatsApp would refuse fails straight away, with a plain sentence such as "Images can be up to 5 MB. This one is 7.2 MB.", rather than at send time. Files are also virus-scanned.

| Kind | File types | Largest file |
| --- | --- | --- |
| **Images** | `image/jpeg`, `image/png` | 5 MB |
| **Video** | `video/mp4`, `video/3gpp` | 16 MB |
| **Audio** | `audio/aac`, `audio/amr`, `audio/mpeg`, `audio/mp4`, `audio/ogg` | 16 MB |
| **Documents** | `application/pdf`, Word, Excel and PowerPoint (`doc`, `docx`, `xls`, `xlsx`, `ppt`, `pptx`), `text/plain` | 100 MB |
| **Stickers** | `image/webp` | 100 KB, or 500 KB when animated |

A megabyte is 1,048,576 bytes. WebP is accepted only as a sticker. These are Meta's own limits, so they are the same whether you upload through `POST /v1/media`, `POST /v1/media/url`, the [Meta-compatible proxy](/migrating/from-cloud-api), the inbox or the media library. See [Media](/sending/media#supported-formats-and-sizes).

### Voice notes

A voice note shows in WhatsApp as a recording with a waveform, not as an audio file. Send one with [`POST /v1/messages`](/sending/messages), `type: audio` and `"voice": true`. Meta expects an OGG file with the Opus codec for this. Without `voice`, audio is sent as an ordinary audio file, which is what you want for an MP3.

### URL import failures

When LazyApp fetches `media_url` for you, the URL must be **publicly reachable** with no auth wall. Meta returns download errors when it cannot fetch bytes — often surfaced as a failed send with a provider error, not a separate LazyApp code.

## Messaging limits

| Limit | Detail |
| --- | --- |
| **24-hour window** | Free-form sends only within 24 hours of the contact's last inbound message — enforced server-side (`customer_service_window_closed`) |
| **New number throughput** | Meta tier often starts at `TIER_250` (~250 unique contacts / 24 h) — see `messaging_limit_tier` on [`GET /v1/capabilities`](/concepts/capabilities) |
| **Number speed** | 80 messages a second per number, 1,000 once Meta upgrades it, 20 on a number shared with the WhatsApp Business app. LazyApp paces sends to stay under it: [Rate limits](/reference/rate-limits#metas-per-number-speed) |
| **One person** | About one message every 6 seconds to the same person, with short bursts allowed. LazyApp paces this too |
| **LazyApp send velocity** | Abuse guards: workspace burst, per-recipient hourly cap, failure-rate pause — [Rate limits](/reference/rate-limits) |
| **API rate** | Set by your plan, per API key — [Rate limits](/reference/rate-limits) |

Broadcasts pace themselves to these limits rather than firing all recipients at once, and the campaign page says when and why — see [Broadcasts](/sending/broadcasts#pacing).

## Analytics

WhatsApp does **not** expose post-level engagement analytics (opens, clicks, funnel) through Cloud API.

What LazyApp gives you instead:

| Signal | Source |
| --- | --- |
| Per-message delivery status | Webhooks: `message.sent`, `delivered`, `read`, `played`, `failed` |
| Broadcast progress | Broadcast status + recipient rows |
| Spend / category | Console **Usage** ledger and [platform usage API](/platform/usage) |
| Quality / tier | [`GET /v1/capabilities`](/concepts/capabilities) + `phone_number.quality_changed` webhooks |

For WhatsApp's own counts of messages, charges and template results, use the [WhatsApp analytics API](/guides/whatsapp-analytics).

## What you cannot do

| Constraint | LazyApp |
| --- | --- |
| Free-form outside the 24-hour window | Send an approved [template](/sending/templates) |
| Message numbers without WhatsApp | Meta rejects — check `message.failed` |
| Use a personal WhatsApp account | WABA + Cloud API required |
| Exceed Meta messaging tier | Tier rises with quality; watch capabilities |
| **Schedule a single message** | **Supported** — `send_at` on [`POST /v1/messages`](/sending/messages#scheduling) (Zernio docs say broadcasts only; LazyApp supports both) |
| Per-message analytics beyond delivery | Webhooks only |

## Common LazyApp error codes

Stable `code` values on API refusals before Meta — branch on these, not `message` text:

| Code | Meaning | Fix |
| --- | --- | --- |
| `customer_service_window_closed` | 24-hour window closed | Send a template or wait for inbound |
| `contact_suppressed` | Contact opted out entirely | Do not retry |
| `marketing_opt_out` | Marketing opt-out | No marketing sends |
| `no_connection` | No WhatsApp connection | Finish [connecting WhatsApp](/guides/connecting-whatsapp) |
| `send_burst_limit` | Workspace send burst, or the number is sending faster than WhatsApp allows | Back off — [Rate limits](/reference/rate-limits) |
| `recipient_rate_limit` | Too many sends to one person: the hourly cap, or WhatsApp's one message about every 6 seconds | Wait the seconds the message names, then retry |
| `failure_rate_paused` | Recent sends mostly failed | Fix connection / recipients |

Full list: [Errors](/concepts/errors).

## Common Meta provider codes

When Meta rejects a send, the message row and `message.failed` webhook carry Meta's numeric code. The console explains each code in plain words, with what to do next. The common ones:

| Code | Meaning | Fix |
| --- | --- | --- |
| **131047** | Re-engagement required — outside the 24-hour window | Send an approved template |
| **131026** | Recipient undeliverable — not on WhatsApp or cannot accept this message | Verify E.164 number and WhatsApp registration |
| **131050** | The customer told WhatsApp they want no marketing from you | Do not send them marketing; service and utility messages still reach them |
| **130403** | The customer blocked your number | Do not send again |
| **132000**, **132001**, **132005**, **132007**, **132012**, **132018** | Template missing, paused, or parameter mismatch | Match template name, language, and parameters exactly |
| **132015** | Template paused for poor feedback | Unpause or edit it |
| **132068**, **132069** | The Flow on the message is blocked, or slowed to 10 messages an hour while it has problems | Fix the Flow and publish it again |
| **131049** | The person has had enough marketing for now | Wait at least 24 hours before trying them again |
| **130429** | The number sent faster than WhatsApp allows (80 a second for most numbers) | Nothing to change; sending slows down and retries |
| **131048** | WhatsApp limited the number because many recent messages were blocked or reported | Check the number's quality and send only to people who asked to hear from you |
| **131056** | Too many messages to one person in a short time (about one every 6 seconds) | Wait a minute and retry |
| **131042** | Meta could not charge the WhatsApp account's payment method | Fix the payment method in WhatsApp Manager |
| **131052**, **131053** | A file could not be downloaded, or WhatsApp could not use the attached file | Re-send a file within the [limits](#upload-limits) |
| **131021** | Sent to your own number | Send to the customer's number |
| **131045** | The number is not fully registered | Finish registering it |
| **131055**, **134100**, **134101**, **134102** | A marketing-route problem: not a marketing template, or Meta has not finished preparing the template | Use a marketing template, or wait 10 minutes after approval |
| **133016** | Registered and removed too many times | Wait for the block to lift |
| **2494100** | The number is briefly in maintenance at Meta | Retry in a few minutes |
| **33** | The number no longer exists at Meta | Connect it again |
| **131031**, **133005**, **133006**, **133010** | Number not registered / account restricted | Re-register in **Connections** |
| **131000**, **1**, **131016**, **2**, **133004**, **4** | A temporary problem at Meta | Retry |
| **10**, **200**, **131005** | A permission LazyApp needs is missing | Reconnect the number and allow every permission |
| **100**, **131008**, **131009** | Meta did not accept part of the message | Fix the detail Meta names |
| **190**, **0**, **3** | Access token invalid or expired | Reconnect the WABA |
| **131037** | Display name not approved | Fix verified name in WhatsApp Manager |

LazyApp returns **`402`** with `code: plan_limit_reached` for a live key on a plan below Pro, and `422` when a broadcast would go past the month's live broadcast sends. That is your LazyApp plan, not Meta. See [Plans and limits](/billing/pricing-and-tiers#plan-limit-reached).

<Warning>
  Do not copy error-code meanings from other BSP docs blindly. Meta assigns codes precisely — **131026** is undeliverable recipient in LazyApp, while **131047** is the re-engagement / closed-window case. Check the failed message in the console or `message.failed` webhook payload for the exact code.
</Warning>
